How it works

A brief is a card. The folder it sits in is its status.

Every project gets a committed board with four folders. A runner moves one card at a time through it, delegating the work to worker agents and writing what happened onto the card itself. Close the window, reopen, and it picks up where the card says.

/spec create

Interview → brief

You describe the product. It asks a few questions about who it's for and what done means, then writes a brief with numbered requirements and testable acceptance criteria into briefs/1-backlog/.

/goal

Runner takes the card

Moves it to 2-active/, breaks it into subtasks in dependency order, infrastructure first. An independent checker model decides when the goal is met, so the loop can't wander forever.

workers

Build with proof

Backend worker writes code and tests against the real Postgres. Frontend worker designs for the product's world and verifies by screenshot. Infra worker deploys and confirms the live commit.

4-done / 3-blocked

Done means verified

A requirement is checked only with evidence in hand. If it truly needs you, the card parks in 3-blocked/ with the question and options. Blocked is never reported as done.

What you get

One repo, provisioned, ready to build in.

  • A monorepo on GitHub — backend/ and frontend/ with health endpoints, pushed on creation.
  • Live services on Render — database, API, and web app created from render.yaml through the API. No dashboard clicking.
  • Claude Code configured inside it — nine skills, three worker agents, hooks that enforce the process rather than remind about it.
  • A readiness check and a teardown — /preflight tells you exactly what's missing and how to fix it; one command deletes the services when you're done.
your-app/
├── backend/            # FastAPI · /health
├── frontend/           # Next.js · /api/health
├── render.yaml         # the one source of truth for infra
├── briefs/             # 1-backlog 2-active 3-blocked 4-done
└── .claude/
    ├── skills/         # spec · orchestrate · preflight · deploy …
    ├── agents/         # backend · frontend · infra workers
    ├── hooks/          # progress guard · trajectory · workspace pin
    └── scripts/        # provision.py · preflight.py

Where it runs

Render today. More clouds on the way.

The factory speaks to your cloud through one adapter. The first one is Render, because a database and two web services come up from a single file with nothing to click.

Get started

Three steps. Claude does the rest.

  1. Get the factory. One line in Terminal.
  2. Open Claude Code in it and type /start. It checks your Mac, walks you through GitHub and Render one step at a time, and asks four questions.
  3. Build. A new repo exists with live services. Open it and /spec create what you want.
git clone https://github.com/nbdesai1992/software-factory.git ~/software-factory
cd ~/software-factory && claude
/start
