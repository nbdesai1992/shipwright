How it works

Your plan is a card on a board. You can always see where it is.

Every project has a simple board: to do, in progress, needs you, done. Your plan moves across it as the work happens, and everything that was done gets written on the card. Close your laptop, come back tomorrow, and it picks up exactly where the card says.

1 · describe

You talk, it writes the plan

Say what the app should do and who it's for. It asks a few follow-up questions, then writes a plan in plain language: a numbered list of what the app must do and how we'll know each part works. You approve it before anything is built.

2 · go

It gets to work

Paste one line and it starts. It breaks the plan into small jobs, sets up the servers first, then works through the list. A separate checker confirms when the plan is truly finished, so it can't run forever.

3 · build

Three specialists, with proof

One writes the behind-the-scenes code and tests it against a real database. One designs the screens to fit your product's world and checks them by taking screenshots. One publishes each piece and confirms it's really live.

4 · done

Done means checked

Nothing is marked done without evidence. If a decision truly needs you, the card waits in "needs you" with a short question and options. Answer in the chat and it continues. Waiting is never dressed up as finished.

What you get

Your own project, set up and already online.

Before you've described a single feature, you already have a real, working starting point. Everything below is created for you in about five minutes.

  • Your code, safely stored on GitHub — a private home for the project that keeps every version. You own it.
  • Your app, already online — a database and two small servers on Render, created for you. No clicking around in dashboards; Shipwright does it.
  • Claude Code, set up inside the project — with the skills and specialists it needs, and guardrails that keep it honest about progress.
  • A health check and an off switch — one command tells you exactly what's wrong and how to fix it; another deletes everything when you're done, and the bill stops.

    └── scripts/        # create the servers · check readiness

Where it runs

Render today. More clouds on the way.

Your app has to live on someone's computers. That's what a cloud provider is. Shipwright works with Render today because it's the simplest place to get a database and a website running with nothing to click.

Get started

Three steps. Claude does the rest.

  1. Get Shipwright. Paste one line into Terminal on your Mac.
  2. Open Claude Code in it and type /start. Claude checks your Mac, walks you through creating your GitHub and Render accounts one step at a time, and asks four questions about your app.
  3. Describe your app. Your project now exists and is online. Open it and tell Claude what to build.

You'll need a Mac, Claude Code, and a credit card for Render. The whole first-time setup takes about twenty minutes, and most of that is creating accounts.

git clone https://github.com/nbdesai1992/shipwright.git ~/shipwright
cd ~/shipwright && claude
